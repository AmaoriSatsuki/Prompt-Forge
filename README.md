# 榫言 · Prompt Forge

![应用图标](src-tauri/icons/128x128@2x.png)

> 用中文思考，产出英文提示词。

**榫言**是一个 Windows 桌面写作工具：把一条中文提示词拆成最多 **9 个模块**，每一排独立产出英文标签流，
专有名词用「胶囊」固定、再由「本地词典」在翻译前钉死，最后拼成一条可以直接粘贴使用的英文提示词。

名字取自榫卯：模块之间要像榫头与卯眼一样严丝合缝地咬合。

- 技术栈：**Tauri 2 + React 19 + TypeScript + Vite + Zustand**（前端）/ **Rust**（后端）
- 平台：**Windows 10/11**（依赖 WebView2，系统自带）
- 翻译服务：当前只接**百度翻译**（腾讯 / 火山 / 阿里为「即将支持」占位）
- 版本：**0.2.0**

---

## 下载即用（推荐）

到 [Releases](https://gitee.com/TsukimiYachiyo/prompt-forge/releases) 下载 `榫言.exe`：

- **免安装单文件**，约 8 MB，双击即用；不写注册表、不需要管理员权限；
- **不需要 Node / Rust / 任何工具链**——那是给想改代码的人准备的；
- Windows 10/11 自带 WebView2，无需额外安装运行库；
- 配置、缓存、词典都写在当前用户目录（`%APPDATA%\com.promptforge.app\`），卸载就是删掉 exe；
- exe 未做数字签名，首次运行时 Windows SmartScreen 可能提示，选「更多信息 → 仍要运行」即可。

> 最新版以 [Releases](https://gitee.com/TsukimiYachiyo/prompt-forge/releases) 为准；旧版 0.1.0（2026-10-20）已被取代。

## 它解决什么问题

把中文提示词直接丢给翻译引擎，通常有两个后果：

1. **专有名词被"意译"掉**：角色名、画师名、风格词，每次翻出来都不一样；
2. **改写类要求失效**：统计机器翻译只会直译，无法执行"语气更礼貌一些"这种指令。

榫言的做法是把这两件事分开：

- **术语**：用胶囊（对象级）+ 本地词典（文本级）在翻译**之前**就固定成你指定的英文；
- **结构**：一条长提示词拆成多排，每排可以单独重翻、单独调高度、单独复制，最后再拼起来。

再加上翻译缓存（命中即不发请求）与串行限速，日常写作时几乎感觉不到等待。

## 功能一览

| 能力 | 说明 |
|---|---|
| 多模块拼装 | 初始 6 排、最多 **9 排**、至少 1 排；**9 色 ↔ 9 排**一一对应，第 10 排被拦下 |
| 中文编辑器 | contenteditable，单模块上限 **1000 个可见字符**（胶囊不占额度；超限只截文字、不丢胶囊） |
| 实时翻译 | 停手 **500ms** 自动翻译，无需点按钮；删空内容即清空译文 |
| 切片翻译 | 中文标点转英文、按行取回；行数不符时逐片段回退重翻；`@画师名`、`(权重:1.2)` 等语法原样保留 |
| 胶囊 | 预设里的术语：从预设库拖入，输出区里点一下即移除；**送翻前先被摘掉、永不进入请求体**，英文只在复制 / 拼接时原样放回 |
| 胶囊权重 | 鼠标悬停在药丸上展开 `− 值 +`（步进 0.05、范围 0.1–3.0，双击可手输）；非 1 时按**括号外顶层逗号**逐段套成 `(tag:1.5)` |
| 预设库 | 权重排序、颜色单选筛选、搜索、右键菜单（权重 ±10 / 编辑 / 删除）；原子落盘 + 损坏留档 |
| 预设分组 | 拖胶囊到面板顶部即建组，折叠 / 展开状态落盘、重启保持；组色 = 建组时那颗胶囊的颜色 |
| Tag 库 | 词典里的 Tag 条目单独成库（`tags.json`），拖进工作区是 Tag 药丸；外观与普通胶囊一致，同样不进请求体 |
| 画师库 | 词典里 `category=1` 的行自动进画师库（`artists.json`）；有 `post_count` 列时默认**只收作品数 ≥ 100**（导入前可改），作品数当权重；`@` 切换视图 |
| 工作区快照 | 把整套模块存成「方案」：`S` 切换快照库、拖到输出区即可整体覆盖（3 层撤销）；每条方案卡上有**更新**（用当前工作区原地刷新）与**复制**（取用保存时的全文） |
| 译文来源顺序 | **胶囊（先摘掉、原样插入，不参与翻译）> 本地词典 > 翻译缓存 > 百度翻译** |
| 翻译缓存 | 键含源文 / 语言 / 引擎 / 词典指纹等，LRU 上限 **1 万条**；设置里可看条数、占用、开关、清空 |
| 输出与复制 | 单排复制、全文复制（模块间「英文逗号 + 空格 + 换行」，空排跳过，**末尾不补句号**） |
| 推送（ComfyUI 联动） | 只监听 `127.0.0.1:<端口>`（默认 **8713**，1024–65535）；帧含全局文本 + 恒定的 9 排；前端 **200ms** 防抖，新连接补收最后一条 |
| 导入导出 | 五库（预设 / 画师 / Tag / 词典 / 快照）打包成单个 JSON；导入只有叠加，同名条目可选**覆盖**或**重命名** |
| 初始化 | 设置里的三档清空：**界面**（主题 / 尺寸 / 分页）、**库**（五个库 + 词典文件夹）、**服务商**（配置 + 系统凭据），后两项需确认 |
| 主题 | 明 / 暗两套，**默认亮色**，手动切换并记住选择 |

> **胶囊不是"翻译源"。** 它在送翻之前就被摘掉，译文里只有中文部分翻出来的英文；
> 术语英文既不进请求体、也不进界面，只在**单排复制 / 全文复制**时原样拼回去。

## 安装与运行

### 直接使用

见上面「下载即用」。当前只发布**免安装 exe**，不提供安装包（`.msi` / `.exe` 安装器永久停用）。

### 从源码构建（仅开发者）

前置：**Node.js 20+**、**Rust stable**（MSVC 工具链）、Windows 10/11（WebView2 已自带）。

```powershell
npm install

npm run tauri dev                     # 桌面端开发（热更新）
npm run tauri build -- --no-bundle    # 只出 exe：src-tauri/target/release/榫言.exe
```

> 第一次构建会下载 Rust crates 与前端依赖，耗时取决于网络；之后增量很快。

## 首次使用

1. 点顶栏的「翻译服务：…」打开设置（也可以按 `Ctrl+,`）。
2. 选「百度翻译」，填入 **APP ID** 与**密钥**并保存 —— 凭据存进 **Windows 凭据管理器**，配置文件里没有明文；
   也可以改用环境变量 `BAIDU_TRANSLATE_APP_ID` / `BAIDU_TRANSLATE_APP_KEY`（界面填写的优先）。
3. 点「测试连接」确认可用，顶栏圆点会变绿。
4. 在左下输入框写中文（用逗号分隔），停手约半秒就会自动翻译。

## ComfyUI 联动（可选）

1. 榫言端：设置 → **推送服务**，确认开关开启、记下**通信端口**（默认 `8713`）。
2. ComfyUI 端：安装插件 **SunYan Sync**（独立项目，暂不随本仓库发布），重启 ComfyUI。
3. 画布上用「榫言中枢 / 榫言模块 / 榫言全局」三个节点：中枢负责接收与分派，模块节点按排取用，全局节点拿剩余文本。
4. 排号对应界面从上到下的第 1–9 排；**两边端口必须一致**，否则节点显示红点。

## 本地词典

顶栏「词典」→「导入新词典」，支持三种格式：

| 格式 | 说明 |
|---|---|
| CSV | 首行表头；自动识别 GBK（Excel 另存的常见编码）与逗号 / 分号 / 制表符 |
| JSON | 对象数组、二维数组、键值映射或 `{entries: […]}` 包装 |
| SQLite | `.db` / `.sqlite`；多表时选择目标表；**只读打开**，不会改动你的原文件 |

字段名命中白名单（如 `cn / 中文名 / cn_name` 与 `en / 英文名 / name`）时静默导入，否则弹出字段映射界面
（两个下拉 + 5 行预览）。导入后统一存成 `[{"cn":"…","en":"…"}]`。

**导入时会把英文里的下划线换成空格**：老词典常见的 `final_fight` 会存成 `final fight`（连续下划线折成一个空格、只改英文一侧，中文键不动）。这一步只发生在导入时——**已经导入过的词典不会被改写**。

**匹配规则是「整段精确匹配」**：忽略首尾空格、可剥掉前导 `@`，但不做子串或分词 ——
写「千早爱音的粉色长发」不会命中「千早爱音」；要命中的话，词典里就放这一整条。

## 数据与隐私

- 所有数据都在本机：`%APPDATA%\com.promptforge.app\`（预设、画师库、Tag 库、配置、缓存、词典、启动日志）。
- 翻译密钥存 **Windows 凭据管理器**，应用**只写不读**（只支持保存 / 查询是否存在 / 删除）。
- 除了调用你自己配置的翻译服务，应用不发起其它网络请求；没有遥测。
- 推送服务只监听 `127.0.0.1`，不对外网开放。
- 会话草稿存在本机 WebView 的本地存储里，下次打开自动恢复。

## 已知限制（刻意如此）

- **仅 Windows**：界面依赖 WebView2，未做 macOS / Linux 适配。
- **仅中文 → 英文**：不支持其它语言方向。
- **模块上限 9**：颜色与模块一一对应，第 10 排会被拦下并提示。
- **只接专业翻译接口**：本版没有接入语言模型或本地模型，重新引入需要重写翻译链路。
- 百度翻译标准版 **1 QPS**、单次 **6000 字节**：批量翻译会有明显间隔，超长内容请拆成多个模块。
- 词典匹配是**整段**精确匹配，不做分词；词典改动只让缓存失效，**不会自动重翻**已有译文。
- 腾讯 / 火山 / 阿里翻译在下拉里可见但不可选（标注「即将支持」）。
- **ComfyUI 插件不随本仓库发布**：需要单独安装 `SunYan Sync`。
- 快照的「复制」取的是**保存时**的全文；想按当前规则重算，用卡片上的「更新」。

## 开发

```
src/                 React 前端
  constants/         颜色、服务商、全部数值约束（唯一真源）
  utils/             纯函数层（零 React、零 IO，断言主力）
  store/             Zustand：纯数据 + 纯逻辑，不发请求
  hooks/             唯一允许「store + api + 编排」混用的地方
  api/               唯一 invoke 出口
  components/        纯展示组件 + 容器组件
  styles/            tokens（两套主题）+ 各区域样式
src-tauri/           Rust 后端
  commands/          translate / config / presets / cache / system / dictionaries
  dictionaries/      CSV / JSON / SQLite 解析与索引
  baidu_translate.rs 百度签名、错误码映射
  storage/           原子写 + 损坏留档
scripts/             11 层离线断言 + 源码体检
```

验证（无需窗口、网络与密钥）：

```powershell
npm run verify                    # 类型检查 + 断言（共 750 项；原 791 含作者本地的文档层 41 项）
cd src-tauri; cargo test          # Rust 单测（107 项）

```

> 判据是**每一层「通过 N 项，失败 0 项」**，不要看退出码：输出经过管道时退出码不可靠。

开发文档（决策记录、踩坑、交接、发布流程）不随仓库发布；`npm run verify` 的文档层在公开副本里会自动跳过。

### 常见问题

**构建卡在「下载工具链」**：只有出安装包时才会触发（本项目用 `--no-bundle`，正常不会遇到）。
若确实遇到，设镜像后重试，成功过一次就会缓存在 `%LOCALAPPDATA%\tauri`：

```powershell
$env:TAURI_BUNDLER_TOOLS_GITHUB_MIRROR = "https://ghproxy.net/"
```

**改了颜色数量**：编辑 `src/constants/colors.ts` 一行即可，派生结果（筛选条、预设库初始宽度等）会自动跟随；
但 `MODULE_MAX_COUNT` 与颜色数量必须相等，有一条断言钉住（当前是 9 色 ↔ 9 个模块）。
